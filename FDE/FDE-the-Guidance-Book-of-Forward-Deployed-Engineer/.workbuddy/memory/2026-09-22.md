## FDE 开源书英文版翻译（全书 13 篇）

**任务**：把 https://fde4.ai/book/ 的《前线部署工程师》（范冰著，v1.0.24）翻译成英文 Markdown，
存到工作目录，每篇标注原文链接 + 作者仓库 https://github.com/xdash/FDE-the-Guidance-Book-of-Forward-Deployed-Engineer 。

**做法（关键决策）**：
- 站点是 VitePress 构建，源码在作者 GitHub 仓库根目录。**没有抓网页，而是从 raw.githubusercontent.com 下载原始 Markdown**
  （用 `od -An -tx1` + `sed` 把中文文件名转成 %XX 百分号编码再 curl），拿到的是最完整的源文本，避免网页清洗丢内容。
- 先写统一规范 `.source/TRANSLATION-BRIEF.md`（术语表 + 姓名标准译名 + 格式硬约束 + 必须的 YAML 前置元数据/标注块模板），
  再按章节分 3 批并行派发子代理翻译，保证 13 篇术语与体例一致。
- 输出文件：`00-Preface.md` … `12-Appendix-C-Case-Index-and-Sources.md` + `README.md`（英文索引），共 14 个，约 432KB。

**踩坑与教训（下次直接复用）**：
1. 子代理译文会**把个别中文词漏译后直接嵌进英文句子**（本次 16 处，如「勉强」「搬运」「维护」「底色」「落题」→「常规/落地/赛道/穿透力/话语权/经过/对标/同级/底层」）。
   必须做一遍「正文残留 CJK 扫描」并按行定位修补。
2. 校验脚本的 frontmatter 剥离逻辑有坑：用 `---` 开关切换会把正文的 `---` 分隔线也当成 frontmatter，导致全部行被跳过、
   扫描结果假阳性为 0。正解是用 `re.sub(r'\A---\n.*?\n---\n','',txt,flags=re.S)` 只剥离开头那段。
3. 子代理会把原文的**粗体小节标记（`**后记**`）擅自提升为标题**，破坏标题数一致性。校验时要比对标题总数并逐个核对。
4. 引用块数量译文会比原文多 2 行，是标注头带来的，属预期，不是缺陷。
5. 附录类文件（人物名单、资料出处）里的中文专名应**刻意在括号中保留**，便于溯源，不算未翻译。

**遗留**：`.source/` 保留着中文原文与翻译规范（隐藏目录），如需清理由用户决定。
